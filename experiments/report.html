Feature spreading with a learned graph

How to classify, or search, a pile of vectors when only one to five examples per class are labeled, and what a learned distance metric adds to the graph-smoothing method this repository started with.

Six datasets of 768-dimensional vectors · up to 5,000 points each · 1 and 5 labeled examples per class · seeds per dataset: pets 5, cars 3, resisc45 3, flowers 3, food101 3, fashion_mnist 3

Summary

  • A learned metric improves the graph, if it is learned from every point. Cluster the points, fit a linear model to the cluster assignments, and use its AGOP as the metric for the neighbor graph. With no labels in the graph, accuracy over feature spreading changes by +3.6 points at 1-shot and +2.1 at 5-shot on average. It is ahead by at least a point on 5 of 6 datasets at 1-shot and never behind.
  • The original AGOP loop stalled for a specific reason. A predictor fit on one example per class only describes those examples. Giving it a target for every point (clusters or pseudo-labels) is the whole fix.
  • Use enough clusters. K = 100 to 400 is level with or ahead of feature spreading on every dataset, whatever the class count. Too few is actively harmful.
  • The same graph helps one-class retrieval. With one exemplar, mean average precision goes from 0.560 (cosine on raw vectors) to 0.723 (cosine on spread features) to 0.784 (PageRank on the cluster-metric graph).
  • Label propagation works once the graph is symmetric. scikit-learn’s kNN version uses a directed graph and scores 0.563 at 1-shot; symmetrizing it gives 0.731, the same as PPR on this repository’s graph.
  • Graph methods can still lose. At 5-shot with default settings a plain SVM on the raw vectors beats every graph variant on cars; lighter smoothing is needed there. The gain is close to zero on fashion_mnist. The all-labels ceiling shows 6 points of headroom at 1-shot that none of this reaches.

1. The problem

You have a few thousand vectors. Each one belongs to a class, but you only know the class for a handful of them: one per class (“1-shot”) or five per class (“5-shot”). The job is to label the rest.

The setting is transductive: the unlabeled vectors are all available up front, and they are the only points that need labels. That matters, because the unlabeled points carry information. They show where the data is dense, which points sit near each other, and where the natural groups are. A method that ignores them throws that away.

The vectors here are image embeddings from a CLIP model, but nothing below uses that. No images, no text, no class names. They are stand-ins for “arbitrary vectors with class structure”, and every method works on any such data.

2. Background: graphs, spreading, AGOP

The method is built from three ideas. Each is simple on its own.

A neighbor graph

Connect every point to the handful of points most similar to it, using cosine similarity. Make the connection mutual: if either point lists the other, they are linked. The result is a k-nearest-neighbor graph. It encodes the assumption that nearby points tend to share a class.

How many neighbors: the code’s setting is k = 10, but because of a strict “greater than” comparison that counts the point itself, each point actually lists 8 neighbors, and its self-loop is counted twice. Every result in this report was produced that way, and “k” below always means the code’s setting (so k = 5 is 3 neighbors and k = 20 is 18). Section 6 checks that this makes little difference.

How true that assumption is can be measured, if you cheat and look at all the labels: edge homophily is the fraction of edges that join two points of the same class. It is a diagnostic used throughout this report. No method here gets to see it.

Spreading: personalized PageRank over the graph

Given the graph, replace each point’s vector with a weighted average of the vectors around it. Close graph neighbors get a large weight, neighbors of neighbors a smaller one, and so on. The specific weights used here are personalized PageRank (PPR): imagine a random walker that starts at a point, and at each step either moves to a random neighbor (with probability α) or jumps back to the start (with probability 1 − α). The weight on any other point is how much time the walker spends there.

All of those weights for all points at once have a closed form. With Â the adjacency matrix (plus self-loops) scaled by node degree, and X the matrix of vectors:

P = (1 − α) · (I − α·Â)⁻¹ · X

α sets the reach. At α = 0 nothing moves. Near 1, every point in a connected cluster collapses to the same average. The repository uses α = 0.85.

What you push through the graph is a choice:

  • Feature spreading pushes the vectors themselves, then trains an ordinary classifier on the labeled rows of the smoothed matrix P. This is the method the repository was written to test.
  • Label propagation pushes the labels. Put a 1 in the right class column for each labeled point, zeros elsewhere, spread that matrix, and give each point the class with the largest value. Same graph, same formula, different payload.

AGOP: which directions does a predictor care about?

Not every direction in a 768-dimensional space is useful for telling classes apart. A distance that weighs all of them equally lets irrelevant variation decide who is whose neighbor.

Take any trained predictor f. Its gradient at a point says which small changes to the input would change the prediction. The average gradient outer product (AGOP) averages ∇f · ∇fᵀ over the data. The result is a d × d matrix G that is large along directions the predictor is sensitive to and near zero along directions it ignores.

Recursive feature machines (RFM) use this as a feedback loop: fit a predictor, compute its AGOP, use the AGOP as the distance metric for the next fit, repeat. It is a way for a kernel method to learn which features matter, which is something neural networks do and plain kernel methods do not.

For a linear predictor f(x) = W·x the gradient is W everywhere, so the AGOP is just WᵀW. No sampling, no kernel. That is the version this report ends up using.

Using G as a metric means measuring similarity after mapping each vector through its square root, x → G^½·x, which stretches the directions the predictor uses and shrinks the rest. A damping weight λ blends it with the ordinary metric so it cannot collapse the space entirely:

M = (1 − λ)·I + λ·G / mean-eigenvalue(G)

3. The first attempt, and why it stalled

The starting idea was a direct RFM loop around feature spreading:

  1. Build the neighbor graph and spread the features.
  2. Fit a predictor on the few labeled points.
  3. Compute its AGOP and turn it into a metric.
  4. Rebuild the neighbor graph under that metric. Go to 1.

On pets at 1-shot (one seed) feature spreading scored 0.771. Four rounds of the loop with a kernel predictor landed between 0.770 and 0.800 depending on settings, and edge homophily moved from 0.814 to about 0.831. At best that is three points on a single seed, from a graph that barely changed, and other settings gave nothing.

Two ceiling experiments showed the idea was sound and the execution was the problem. Both cheat by using every true label, so they are upper bounds and not methods:

  • Delete every edge that joins two different classes, then run feature spreading as usual: 0.937. So the graph is the bottleneck, with about 17 points of headroom.
  • Compute the AGOP from a classifier trained on all labels, rebuild the graph with it, then run the normal 1-shot method: 0.921. So an AGOP metric can deliver most of that headroom.

The loop stalls because of what feeds it. A predictor fit on one point per class only knows about those few points. For a linear model this is exact: its weights are a combination of its training vectors, so its AGOP spans at most as many directions as there are labeled points, and those directions describe the labeled points, not the classes. A kernel model has the same limitation in a softer form, since everything it knows about the labels still comes from those few points. Rebuilding the graph with that metric mostly connects points the classifier already thought were similar. Nothing new enters the loop.

The fix follows from that diagnosis: give the predictor a target for every point, not just the labeled ones.

4. The method that works

  1. Graph and spread. Build the neighbor graph on the raw vectors X and spread them to get P, exactly as before.
  2. Make a target for every point. Either run k-means on P and use the cluster assignments (no labels involved), or train the few-shot classifier on P and use its predictions for all points as pseudo-labels. Or use both side by side.
  3. Fit a linear model to those targets. Ridge regression from P to the one-hot targets, which is a single linear solve. Call the weights W.
  4. Take its AGOP as a metric. G = WᵀW, damped with λ = 0.5.
  5. Rebuild the graph under the metric on the raw vectors, and spread the raw vectors over the new graph.
  6. Classify. Train the SVM on the labeled rows of the new P, or run label propagation on the new graph. Optionally repeat from step 2.

The metric only decides who is whose neighbor. The vectors being averaged are still the original ones. And when the targets are k-means clusters, the graph is built without any labels at all; the labels are only used by the final classifier.

Why should cluster assignments work as targets? The clusters are found in the smoothed space, where spreading has already pulled natural groups together. A linear model that can predict those groups has to pick out the directions along which the groups differ. Those directions are a good guess at the ones that separate the real classes too, and the metric emphasizes exactly them.

5. Classification results

Every number is accuracy on the unlabeled points, averaged over seeds (each seed draws a different sample of points and a different labeled set). Settings were fixed in advance and are the same for every dataset: k = 10 (8 real neighbors), α = 0.85, K = 100 clusters, λ = 0.5, ridge penalty 1. Cluster targets use one round, pseudo-label targets use three. The final classifier is a linear SVM trained on the labeled points only.

  • Cluster targets (no labels in the graph). +3.6 points on average at 1-shot (range +0.3 to +8.3), ahead of feature spreading by at least a point on 5 of 6 datasets and level on the rest. At 5-shot: +2.1 on average (range +0.7 to +3.6), ahead by at least half a point on all 6.
  • Pseudo-label targets. +3.7 points on average at 1-shot (range -1.9 to +10.3) and +2.6 at 5-shot (range -0.1 to +5.2). Below feature spreading at 1-shot on: fashion_mnist (-1.9). At 5-shot: fashion_mnist (-0.1).
  • Both targets together average +4.2 at 1-shot and +2.8 at 5-shot.
  • Label propagation on the learned graph scores +2.3 points relative to the SVM on the same cluster-metric graph at 1-shot, and +0.5 at 5-shot, on average. It is the better final step when labels are scarcest.
  • Remaining headroom. A metric built from all the true labels is still 6.4 points above the best real variant at 1-shot, averaged over datasets, and 3.3 at 5-shot.

Graph methods are not always the right tool. At 1-shot every graph method beats the plain SVM on every dataset. At 5-shot a plain SVM on the raw vectors beats the original feature spreading on cars, and beats every graph variant tested on cars. These comparisons use the default graph settings; section 6 shows that lighter smoothing changes the picture at 5-shot.

Seed-to-seed variation at 1-shot is large on some datasets, because one labeled example per class can be a lucky or unlucky draw. The standard deviation of feature spreading across seeds ranges from 0.002 to 0.074 depending on the dataset; for the cluster-metric graph it is 0.005 to 0.094. Differences of a point or less between variants should not be read as real.

6. Tuning and ablations

Each test changes one thing from the default and keeps the rest fixed. The default is k-means with K = 100 on the smoothed features, λ = 0.5, ridge penalty 1, one round, SVM on the labeled points.

How many clusters

The number of clusters does not need to match the number of classes, and the method does not need to know the class count. What matters is having enough clusters. A ridge model with K outputs produces a metric with at most K − 1 directions, so a small K squeezes the graph into a space too small to hold the class structure.

  • K = 10 is harmful: mean 1-shot accuracy 0.605, against 0.717 for feature spreading with no metric at all.
  • The best single setting on average is K = 100 at 1-shot (0.752) and K = 100 at 5-shot (0.852). Beyond that, accuracy falls off slowly: K = 400 averages 0.742 at 1-shot.
  • K = 100, 200 and 400 are level with or ahead of feature spreading on every dataset at both shot counts. K = 50 is not: at 1-shot it falls short on flowers and food101, the two datasets with about 100 classes.
  • Best K per dataset at 1-shot: pets 50, cars 100, resisc45 100, flowers 200, food101 200, fashion_mnist 400. The link to the class count is loose (cars has 196 classes and is best at 100; fashion_mnist has 10 and is best at 400), so the practical rule is to err high.

An earlier run set K equal to the class count. That was the cause of a loss on fashion_mnist, which has 10 classes: with K = 10 the cluster-metric graph scores 0.537 there at 1-shot, and with K = 100 it scores 0.585, level with feature spreading (0.582). The metric no longer hurts on that dataset, and it does not help either.

Metric strength, ridge penalty, rounds

  • λ (how much of the learned metric to use). Mean 1-shot accuracy is 0.741 at λ = 0.1, 0.752 at 0.5 and 0.756 at 1.0. More is slightly better and nothing breaks at 1.0, where the plain metric is dropped entirely.
  • Ridge penalty. 0.736 at 0.01, 0.743 at 0.1, 0.752 at 1 and 0.745 at 10 (mean 1-shot accuracy). The default of 1 is the best on average. A penalty of 0.01 costs 1.7 points and a penalty of 10 costs 0.7.
  • Rounds. One round gets nearly everything. With cluster targets, mean 1-shot accuracy is 0.752 after one round and 0.757 after four. With pseudo-label targets it is 0.748 after one and 0.753 after three. Pets is the exception: pseudo-label rounds take it from 0.832 to 0.861.

Which parts are doing the work

  • The targets need real structure. A metric fit to random targets makes things worse (-3.1 points on average). The gain is not a side effect of passing the data through a ridge regression.
  • It is not a principal-component effect. Keeping the top 100 principal directions of the smoothed features changes nothing (+0.2), and whitening them is harmful (-5.7). The ridge model picks directions that separate clusters, which is different from picking directions with high variance.
  • Re-graphing alone gets part of the way. Rebuilding the neighbor graph on the smoothed features, with no metric at all, gives +1.4 points on average. The cluster metric gives +3.6. So part of the benefit is simply “build the graph twice”, and the metric adds the rest.
  • Smoothing before clustering is optional. Running k-means and the ridge fit on the raw vectors gives +3.7, about the same as the default. The simplest version of the method is then: k-means on the raw vectors, ridge regression, metric, graph, spread.
  • Build the new graph from the raw vectors. Applying the metric to the smoothed features and building the graph from those is worse (+2.4).

Neighbors and restart probability

On average the learned metric helps at every graph setting tried: it is ahead of feature spreading at the same k and α in all five combinations, at both shot counts.

The best amount of smoothing depends on how many labels there are. With one label per class, heavy smoothing is right: α = 0.85 averages 0.752 with the cluster-metric graph, against 0.722 at α = 0.5. With five labels per class, lighter smoothing is better: α = 0.5 averages 0.860 and k = 5 averages 0.861, against 0.852 at the default. The difference is largest on cars, where the default cluster-metric graph scores 0.748 at 5-shot, below the plain SVM (0.780), and α = 0.5 scores 0.796, above it. Pushing α up to 0.95 lowers the average at both shot counts, with or without the metric.

Kernel or linear AGOP

The original idea used a kernel predictor, whose AGOP has to be computed by averaging gradients over every point. The linear version is a single matrix product. Where the kernel version was affordable (50 classes or fewer), the two are close: kernel is up to a point and a half ahead at 5-shot and about the same at 1-shot, at many times the cost.

  • Unsupervised graph tweaks (centering the vectors, changing k or α, weighting edges by similarity) move accuracy by about a point, and that is after picking the best of 72 settings using the test labels.
  • Self-training without changing the graph does not help, and gets worse with more rounds as wrong pseudo-labels reinforce themselves.
  • Deleting edges between points with different predicted labels is the direct imitation of the “no cross-class edges” ceiling. It does nothing, because the edges it removes are the ones the classifier already agreed with.
  • A class-mean metric (directions between the pseudo-class averages, no regression) helps a little at 1-shot and not at all at 5-shot. The ridge fit matters: it also accounts for how the data is spread within classes.
  • Applying the metric to the features the classifier sees, instead of to the graph, is clearly worse. Applying it to both is no better than the graph alone.
  • Training the final classifier on pseudo-labels is worse than training it on the few true labels over the improved features.

7. Label propagation, and why sklearn’s fails here

The repository was written partly because label propagation “basically didn’t work” on this kind of data. That observation was about scikit-learn’s implementation, and it still holds in the current version (1.9.1). It is a property of the graph that implementation builds, not of label propagation as an idea.

With kernel='knn', scikit-learn builds a directed neighbor graph: row i lists the points that i considers its nearest neighbors, and the update step has each point pull label mass from its own list. Information therefore flows from a labeled point only to points that list it. In high-dimensional data a noticeable share of points appear in nobody’s list. Here that is 5% to 12% of the labeled points, depending on the dataset. When the single labeled example of a class is one of those, its label never leaves it, and the whole class is unreachable. That is the extreme case. More generally, how far a label travels depends on how many points happen to list the labeled one, and in high dimensions that count is very uneven: a few points are in hundreds of lists and many are in almost none.

The test is to swap in the symmetrized graph (two points are linked if either lists the other) and change nothing else:

  • LabelSpreading as shipped averages 0.563 at 1-shot. With the symmetrized graph it averages 0.731, level with PPR on one-hot labels over this repository’s graph (0.732). At 5-shot: 0.776, 0.831 and 0.833.
  • LabelPropagation as shipped is worse still (0.415 at 1-shot). It also clamps the labeled points hard and iterates until convergence, and it hit the 2,000-iteration limit on 26 of its 36 runs.

So label propagation is a reasonable baseline once the graph is right. On the base graph it is close to feature spreading (mean accuracy 0.732 against 0.717 at 1-shot, 0.833 against 0.831 at 5-shot), ahead on some datasets and behind on others. Whether scikit-learn’s behavior changed between versions was not checked; the directed graph is enough to explain what was seen.

8. One-class retrieval

A different question from classification: you have one example (or five) of a single class and want to find the rest of that class in the pile. There are no labels for any other class, no negatives, and the number of classes is unknown. The output is a ranking of every other point.

Two measures are reported. Average precision walks down the ranking and averages the precision at each true match, so it rewards putting all members of the class near the top; its mean over queries is the headline number. Precision in the top 10 is the fraction of the first ten results that are correct. Each (dataset, seed) uses at least 100 queries, with exemplars drawn at random from each class.

The scorers:

  • Cosine similarity to the exemplar. With one positive and nothing else, this is what a linear classifier reduces to.
  • One-vs-rest classifier: the exemplar as the positive, unlabeled points as negatives. Tried as a linear SVM against 500 random points and as a closed-form ridge fit against all points.
  • Query expansion: add the top 10 results to the query and search again. A standard retrieval trick, included as a non-graph baseline.
  • PageRank from the exemplar: the PPR weights the exemplar assigns to every other point. This is label propagation with a single class.

Each scorer can run on the raw vectors or on features spread over a graph, and the graph can be the plain neighbor graph or the cluster-metric graph from section 4. The cluster-metric graph uses no labels, so it is built once and shared by every query.

  • Spreading helps retrieval a great deal. Mean average precision with one exemplar goes from 0.560 for cosine on raw vectors to 0.723 for cosine on spread features, averaged over datasets.
  • The cluster-metric graph adds to that. PageRank on it averages 0.784, against 0.734 on the plain graph, and is ahead on all 6 datasets. With five exemplars: 0.858 against 0.828, ahead on all 6.
  • Best scorer. With one exemplar: “PageRank, cluster-metric graph, 2 rounds” (0.786; one round gives 0.784). With five: “One-vs-rest ridge, cluster-metric graph” (0.873).
  • A one-vs-rest classifier needs spread features, or more than one exemplar. With one exemplar on raw vectors the SVM averages 0.559 and the ridge version 0.593, against 0.560 for plain cosine: little or no gain. Trained on features spread over the cluster-metric graph, the same SVM reaches 0.768. With five exemplars the classifier earns its place: 0.816 on raw vectors against 0.687 for cosine, and 0.864 (SVM) or 0.873 (ridge) on the cluster-metric graph.
  • The metric needs the graph. Cosine similarity under the learned metric, with no graph or spreading, averages 0.660. That is better than raw cosine and well short of the graph versions.
  • Query expansion on raw vectors reaches 0.596: a small gain for a small change, far below spreading.
  • The top of the ranking moves less. Precision in the top 10 with one exemplar is 0.793 for raw cosine, 0.840 on spread features and 0.861 on the cluster-metric graph. The nearest few neighbors are mostly right already; the graph mainly helps find the members of the class that are far from the exemplar.
  • Headroom. The all-labels ceiling is 0.870 with one exemplar and 0.915 with five.

Retrieval settings

The number of clusters behaves as it does in classification: too few hurts, K = 50 is not enough for the datasets with about 100 classes, and 100 to 400 is safe. For the PageRank scorer, a restart setting of α = 0.95 is the best on average on both graphs.

A metric built for each query

9. Recommended recipe

For few-shot classification or one-class search over a fixed set of generic vectors:

X      = normalize(X)                                   # rows to unit length
labels = kmeans(X, K=100)                               # K = 100–400; too few clusters is harmful
                                                        # (clustering raw X scored the same as clustering spread X)
W      = ridge(X, one_hot(labels), penalty=n / 5000)    # one linear solve; W is K × d. Penalty 1 was tuned at
                                                        # n ≈ 5,000; scale it with n to keep the same strength
G      = W.T @ W                                        # AGOP of the linear model
M      = (1 - lam) * I + lam * G * d / trace(G)         # lam = 0.5 (anything from 0.5 to 1 is fine)
adj    = knn_graph(normalize(X @ sqrtm(M)), k=8)        # 8 real neighbors (what the code's k=10 does); 10 is
                                                        # within about half a point. Mutual: linked if either lists the other
P      = normalize(ppr(adj, alpha=0.85) @ X)            # spread the ORIGINAL vectors

# classification, few labels per class
clf    = LinearSVC().fit(P[labeled], y[labeled])        # or: argmax of ppr(adj, alpha=0.95) @ one_hot(y_labeled)

# retrieval, one class
scores = ppr(adj, alpha=0.95) @ indicator(exemplars)    # rank by score
  • With 1 label per class, prefer label propagation on the learned graph as the final step. With 5, the SVM and label propagation are close.
  • With 5 labels per class, smooth less. α = 0.5 (or k = 5) is better than the default by about a point on average and by several points where the neighbor graph is poor.
  • Pseudo-labels are an optional extra. Adding the classifier’s predictions as targets next to the clusters, for three rounds, is worth +0.6 points at 1-shot and +0.7 at 5-shot on average, and costs a classifier fit per round.
  • For retrieval with several exemplars, a one-vs-rest classifier trained on P is as good as or better than PageRank. With one exemplar, use PageRank.
  • Check against a plain SVM on the raw vectors. When the base neighbor graph is poor, spreading of any kind can lose to it, and there is no label-free test here that predicts when.
  • Cost. k-means, one d × d solve, one extra neighbor search and one extra PPR solve. In these experiments PPR is a dense n × n solve, which is fine at 5,000 points and would need a sparse or iterative solver beyond a few tens of thousands.

10. Caveats

  • Few seeds. pets 5, cars 3, resisc45 3, flowers 3, food101 3, fashion_mnist 3. One-shot accuracy varies by several points between seeds on some datasets. Averages over datasets are more trustworthy than any single cell.
  • Settings were chosen with test labels in view. There is no validation set at 1-shot. The defaults (K = 100, λ = 0.5, ridge 1) were fixed as the center of the sweeps before the cross-dataset runs, and the sweeps show accuracy is flat around them, but the earlier exploration that led to this design used pets heavily. Pets is also where the gains are largest.
  • One kind of vector. All six datasets are embeddings from the same image model. The methods are generic, but the results have not been checked on embeddings from other models, on text, or on tabular data.
  • Subsampled. Each run uses at most 5,000 points. Neighbor graphs get denser and usually better with more points, which could shrink or grow these gaps.
  • Settings tuned at one size. The ridge penalty of 1 is not scaled by the number of points. The quantity it is added to grows in proportion to n, so on a much larger collection the same penalty is relatively weaker; scaling it as n / 5,000 keeps the tested strength. The cluster count (100) and neighbor count were likewise only tested at 3,700 to 5,000 points.
  • Transductive only. Every method here labels the points it was given. Labeling a new point later would need it to be added to the graph.
  • Retrieval negatives. The one-vs-rest scorers treat unlabeled points as negatives, some of which are true positives. That matches the real setting and is part of why those scorers do poorly with one exemplar.
  • The ceilings are not targets. They use all labels to build the graph. They show the graph is still the limiting factor, not what a label-free method could reach.

12. Glossary

1-shot, 5-shot
One, or five, labeled examples per class. Everything else is unlabeled.
Transductive
The points to be labeled are all available while the method runs, so it can use their positions.
kNN graph
Each point is linked to its most similar points by cosine similarity, links made mutual. The code’s k = 10 gives 8 real neighbors.
Edge homophily
Fraction of graph edges joining two points of the same class. Needs all labels, so it is only a diagnostic.
PPR
Personalized PageRank. The weights a restart-prone random walk assigns to the points around its start.
α (alpha)
Probability the walk continues instead of restarting. Higher means smoothing reaches further. Default 0.85.
Feature spreading
Smooth the vectors with PPR, then train a normal classifier on the labeled rows.
Label propagation
Smooth a one-hot label matrix with PPR and take the largest entry per point.
AGOP
Average gradient outer product of a predictor: a matrix describing which input directions it is sensitive to.
RFM
Recursive feature machine. Alternates fitting a predictor and re-weighting the input space by its AGOP.
Ridge regression
Least-squares linear regression with a penalty on large weights. Solved in closed form.
Pseudo-labels
A classifier’s own predictions on unlabeled points, treated as if they were labels.
λ (lambda)
How much of the learned metric to mix with the plain one. 0 is plain cosine, 1 is the learned metric alone.
Average precision
For a ranked list, the mean of the precision measured at each true match. 1.0 is a perfect ranking.
Ceiling / oracle
A result computed using every true label, to show how much room is left. Never a usable method.
